# 《活到战争结束》

**《活到战争结束》** 是一款完整的浏览器生存游戏，故事发生在 1917 年 2 月至 1918 年 11 月 11 日 11:00 休战前夕的西线战场。

你不是将军，无法改写历史。你只是一个普通的英国士兵，必须守住自己的健康、判断力、人际关系，以及足够的希望，最终活着回家。寂静的日子、糟糕的食物、来信、工作队、谣言，以及等待，都和炮火一样重要。

## 运行方式

要求：Node.js 20 或更高版本。

```bash
npm install
npm run dev
```

打开 Vite 输出的本地地址即可。安装依赖后不需要 API 密钥、账号、数据库或网络连接。

完整界面与叙事内容支持 English 和 Simplified Chinese（简体中文）。在开场页、人物记录、战地日记或结局界面中可切换 EN / 中文；语言偏好会保存在浏览器中，并且无需重启人生即可切换。

生产与验证命令：

```bash
npm run build       # 类型检查并生成 dist/
npm test            # 运行确定性的引擎和浏览器流程测试
npm run simulate    # 自动游玩 1,000 次完整人生
npm run preview     # 在本地预览生产构建
```

可通过 `npm run simulate -- 250` 指定更小或更大的模拟次数。也可以添加第二个参数来审计策略：`balanced`、`first`、`second`、`careful` 或 `bold`（例如：`npm run simulate -- 1000 careful`）。

## 如何游玩

1. 选择 **EN** 或 **中文**，然后开始新的一生，并创建或生成一份服役记录。
2. 阅读当前场景并选择一个回应。所有可用选项都有效；没有任何选择可以保证安全。
3. 关注健康和士气。高压、饥饿和疲劳都非常危险。
4. 随着月份推进，打开分段掷骰、战地日记、信件和档案。
5. 生存下来、被送回国、被俘，或者在停战前死亡。

游戏会在角色创建和每次选择后自动保存。`Continue` 可恢复完整日期、PRNG 状态、NPC 状态、信件、日记和当前事件。也提供手动的 **Save record** 保存控制。

## 已实现内容

- 开场序列、角色生成、种子挑战运行，以及一条完整的英国路线。
- 完整的 English 和 Simplified Chinese（简体中文）界面、本地化事件、选择、结局、日记、信件、战友、历史与结尾内容，并支持持久化游戏内语言切换。
- 动态时间：普通事件会跳过数天；危险行动可能推进数小时或数分钟。
- 63 个日常/生存事件、16 个战斗事件、20 个互相关联的 NPC 故事事件、6 个战役章节场景、10 封信件和 12 条固定历史记录。
- 健康、士气、压力、饥饿、疲劳、隐藏运气、装备、天气，以及情境化危险。
- 五位持久化虚构战友，拥有四阶段个人弧线、分支回调、关系、受伤、死亡、被俘、调动和恢复。
- 历史固定事件包括阿拉斯、第三次伊珀尔、康布雷、德军春季攻势、第二次马恩河会战、百日攻势和停战背景。
- 战地日记、保留下来的信件、人员名册、战地地图、历史档案，以及可见的事实/虚构标签。
- 阵亡、伤重死亡、因伤离队回国、战俘、以及停战生还等结局。
- 安静的 10:58–11:00 停战序列和种子化战后生活记录。
- 可选本地生成的风声/无人机氛围音，并带有静音控制；无外部音频资源。
- 响应式桌面/移动端展示，支持减少动画模式。

## 机制说明

每个选择都带有作者编写的效果，并在适当情况下带有基础危险。引擎会根据身体状态、疲劳、压力、士气、隐藏运气、姿态、天气和装备来调整风险。一个谨慎的回答仍可能失败；一个大胆的回答也可能成功；随机性与单次重复信件都不能决定一切。

所有重要的随机抽取都来自已保存的 Mulberry32 状态。相同的种子和相同的选择会产生相同的关键结果，包括事件选择和伤亡。音频纹理仅作装饰，不参与游戏随机。

历史事件在时钟跨越对应日期时触发。玩家可以阅读、讨论或返回工作，但这些回应不会改变事件本身。

事件会记住出现次数和距离上次出现的时间。一次性场景不会重复；战斗场景有较长冷却时间；未见过的素材优先出现；选择可能安排后续后果。六个重大历史里程碑会打开作者编写的章节场景，而每位战友的个人线则通过四个相连阶段推进，并可能被伤口或死亡打断。

## 技术与架构

- React 19、TypeScript、Vite
- 纯作者 CSS（无外部字体、图片或运行时样式）
- 纯 TypeScript 规则与 JSON 式本地数据
- `localStorage` 保存方案
- Vitest + jsdom

```text
src/
├── components/      开场、创建、游戏、档案和结局视图
├── data/            历史记录、信件、NPC、事件目录
├── game/            类型、PRNG、引擎、存档、模拟、呈现
├── hooks/           可选程序化环境音效
├── i18n/            UI 字典和完整中文作者内容包
└── styles/          受档案风格启发的响应式视觉系统
scripts/
└── simulate.ts      使用真实游戏规则的平衡模拟器
docs/
├── DESIGN.md
├── HISTORICAL_NOTES.md
└── screenshots/     发布截图存放位置
```

引擎本身不依赖 React。英文作者文本保持为保存时的规范表示，而本地化在展示层完成；因此切换语言不会改变种子、掷骰结果、事件结果或保存的生命。测试和模拟器都使用与 UI 相同的 `resolveChoice` 路径。

## AI 层

版本 1 中刻意没有 AI 依赖。完整游戏可离线运行。未来可选的适配器可能修饰表层文案，但不得改变时间线、规则、随机掷骰、结果、存档状态，也不得改变普通士兵所能知道的事。

## 历史设计

固定公开事件与虚构个人事件在界面中被明确区分。五位战友、玩家、家人、信件、日记 prose，以及地方性事件都是虚构组合。日期和研究来源写在 [docs/HISTORICAL_NOTES.md](docs/HISTORICAL_NOTES.md)；实现边界在 [docs/DESIGN.md](docs/DESIGN.md)。

## 平衡快照

最终 1,000 次平衡模拟结果为：

```text
活到停战：182
阵亡：540
伤重死亡：84
因伤回国：162
战俘：32
停滞：0
平均回合：79.4
```

在活到停战的幸存者中，平均完整人生持续 120.4 回合，精确事件重复率为 8.7%，完成了 4.9/5 个战友个人弧线，并且 6 个战役章节场景均已出现。

这是游戏平衡目标，而不是对 1917 年英国部队真实统计经验的主张。
